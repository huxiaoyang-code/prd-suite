# PRD 校验

对写好的 PRD 做核对，**只输出缺失清单，不改文档**。改不改、怎么改由用户决定。

**建议在新会话里跑。** 用户在同一轮里要求校验时提醒一句，坚持就照做。

可以脱离前三步独立使用——拿一份别人写的 PRD 来查也行。没有 alignment.md 时跳过第七、八项，并说明跳过了。

第九项查的是写作时管不住的整篇属性——这类规则在写到第 300 行时靠记性不可靠，只能写完回头查。

工作区与文件格式见 `AGENTS.md`。

---

## 九项检查

**不要发明检查项**，只查这九项。文档啰嗦、章节顺序不合意、措辞不够专业，都不在范围内。

| # | 查什么 | 反向也要查 |
|---|---|---|
| 一 | mockup 里的每个区域编号，PRD 是否都有对应小节 | PRD 写了 ④，mockup 上没有 ④ |
| 二 | 每条承重规则是否都配了验证表 | 有没有给非承重规则也配表（文档虚胖） |
| 三 | 验证表第三列是否都填了具体判定 | — |
| 四 | 页面上每个数字是否都在紧邻位置写了口径 | — |
| 五 | PRD 提到的每个状态，mockup 是否都有对应可切状态 | mockup 有这个状态按钮，PRD 没写该状态下的规则 |
| 六 | 是否有能力被提到、但既没写怎么做也没写本期不做 | — |
| 七 | 每条承重规则能否追溯到 alignment.md 的某条 C 编号 | — |
| 八 | mockup 的结构是否与 C 区确认的形态一致 | D 区已否决的形态有没有被画回来 |
| 九 | 整篇属性：背景是否 2~4 句、全文是否在 300~450 行、是否有整节为空却写了「无」 | — |

承重规则的判定标准：数字计算、状态流转、边界处理、权限可见性。

第四项重点查余额类、累计类、占比类、剩余天数类。

第七项追溯不到的标注「写作时补充，未经确认」，请用户逐条确认或推翻。查的是有没有凭空冒出来的规则，**不是逐字一致**——规则被展开、被细化是正常的。

### 第三项的判定标准

| 不合格 | 合格 |
|---|---|
| 符合预期 | 提示文案出现且按钮不可点 |
| 正常显示 | 确认弹窗出现且含原值和新值两个数字 |
| 功能可用 | 列表返回 0 条且显示空态文案 |
| 按规则处理 | 提交被拦截且原值不变 |

## 输出

按检查项顺序列，九项全部要有结论，通过的也不能省略。

通过的一行带过：`一、区域覆盖 —— 通过（6 个区域全部有对应小节）`

不通过的列出**具体位置和具体缺什么**，不要写「部分区域缺少说明」这种没法直接改的话：

```
三、判定列的质量 —— 3 处不合格

  R3-2 下调确认，第 2 行
    当前：判定列写「按规则弹窗」
    问题：没说清弹窗里要有什么，无法核对
    建议：确认弹窗出现，且文案中同时包含原值和新值
```

最后给一句整体判断：可以评审了 / 建议补完 X 项再评审。

**不要顺手把文档改了**，也不要给出修改后的完整段落，只给到「建议」这一层。

**不要评价需求本身好不好、方案合不合理**——那是对齐环节的事。

## 补丁区

模型变强后应整段删除。

**建议在新会话里跑。** 因为模型对自己刚写完的内容有惯性，难以客观核对。等模型能稳定自我批判时删掉。

**第三项给了具体例句。** 因为模型对「可机械核对」的把握不稳。等能稳定判断时简化成一句原则。

**九项逐条列出。** 为了防止漏检和防止发明新检查项。等模型能稳定按原则自行推导时可以压缩。
